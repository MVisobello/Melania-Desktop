# Stage 99 — verified QEMU DRM pixels after native minimize and restore

## Objective

Stage97 proved the real Smithay `xdg_toplevel.set_minimized` and Melania Panel `ACTIVATE` IPC roundtrip, but the client in that probe did not paint pixels. This stage proves that a *retained real Wayland wl_shm image* disappears from and later reappears on the **actual QEMU display** after compositor-only state changes.

## End-to-end evidence (single disposable VirtIO-GPU guest)

1. Existing two-window client A/B sends twelve independent `wl_shm` buffers to the native Smithay scene and receives its twelve callbacks **only after** kernel FB_ID/connector routing ACKs.
2. After A11/B12, the client leaves both real `xdg_toplevel` surfaces connected. It sends `MINIMIZE 1` using the same bounded Unix IPC as Melania Panel. It does **not** commit a new pixel buffer.
3. The compositor's retained `DynamicWindowScene` masks A and invalidates its rectangle. A compositor-generated KMS **frame 13** must be presented; the DRM receiver checks the actual kernel CRTC framebuffer and connector routing. The independent host QMP watcher captures PPM pixels while the real framebuffer is live, proving A's previous interior is background and B still shows its unchanged B12 pixels.
4. Only after the compositor has processed the KMS13 ACK does a guest-local sentinel authorize `ACTIVATE 1`. The compositor restores the retained A11 buffer, invalidates damage and raises A. **Frame 14** must be presented without a new `wl_shm` buffer. The QMP watcher verifies A11 pixels and B12 pixels are correctly preserved on the real virtual GPU.
5. The receiver restores the previous Linux console framebuffer and verifies connector/CRTC restoration; both independent actions and the guest host harness must report success.
6. An erroneous frame, stale pixel, missing KMS/connector ACK, absent screenshot or QMP capture after the guest exits fails the GitHub Actions run. The live PPM images are retained as CI artifacts; synthetic byte fixtures are used only to unit-test the strict verifier.

## Isolation and correctness

- The fourteen-frame mode is explicitly gated behind `MELANIA_NATIVE_MANAGED_MINIMIZE_QMP=YES_QEMU_VM` and `MELANIA_NATIVE_QEMU_FRAME_TARGET=14`; other scenarios retain their existing budget.
- The receiver expects fourteen real CRTC verifications. The compositor requires exactly twelve Wayland client callbacks: frames 13 and 14 are generated by the shell without new client buffers or callbacks.
- The first window's `ManagedWindow` minimized state, `DynamicWindowScene` visibility, second window visibility and both surfaces' lifetime are checked after each of the final two KMS acknowledgments.
- The client and tests fail closed on socket errors, invalid IPC state, missing explicit post-KMS sentinel or corrupted screenshot pixels.

## Still not a standard desktop session

This proves one specific QEMU VirtIO GPU window transition and real scanout. It does not implement DRM/GBM reacquisition across VT pause/resume, robust multi-output modesetting, a production window manager, screen locking and login integration, Xwayland or the complete XFCE feature set. `NATIVE_SESSION_READY=false` and the production login gate remain unchanged.
